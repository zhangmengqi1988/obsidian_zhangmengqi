Matt Pocock 是 TypeScript 教育者、Total TypeScript 作者，也是 AI 编码工作流的活跃实践者，维护着自己的 skills 仓库（开源）。这场直播演示的是他自研的 Wayfinder 工具——一个 agent 编排器，定位在"spec 之前的探索阶段"。  
  
Wayfinder 是 GrillMe 技能的升级版。GrillMe 是单一 grilling 会话，而 Wayfinder 是 grilling 会话的编排器：它会先扫描代码库、理清现状，然后把一个宽泛的需求拆成多个聚焦的小 grilling 会话并行跑，每个会话对应一个决策点。最终输出是一份决策完备的 spec，可以直接交给实现 agent 去构建。  
  
直播里 Matt 用一个真实需求做演示：给自己的 Course Video Manager（CVM）加一个 TikTok 创建器。从最初口述需求、让 Wayfinder 绘制"地图"、回答 grilling 问题、创建决策/研究/原型 ticket、并行多 session 推进、讨论 schema（format 用 enum 还是 boolean）、原型 UI 变体、到 render pipeline 归属和 TikTok posting lifecycle。整个流程把"雾里看花"逐步推成了清晰的 spec。  
  
看点：  
\- Wayfinder 如何把一个模糊需求拆解成 9 个可执行的决策 ticket  
\- 决策 ticket vs 实现 ticket 的区别：前者靠做决策解决，后者靠代码实现  
\- 多个 grilling 会话并行跑时怎么协调、怎么处理 blocking 关系  
\- prototype 技能：把抽象讨论提升到可点击的 UI 保真度  
\- Matt 对 model / harness / environment 三层架构的理解：换 model 不是唯一解  
\- 真实工程权衡：enum vs boolean、Remotion 是否独立成仓库、TikTok 审计墙怎么绕  
  
关键内容：  
\- Opus 4.8 medium 足够用，不需要更聪明的模型，medium 在质量和延迟间最平衡  
\- effort 权衡的是质量和延迟，越高边际收益越递减  
\- agent = 新上下文窗口 + skill，所以自己用 skills 管理就够了，不一定要专门 agent  
\- vibe coding 只在原型阶段，原型会喂给 spec，spec 才是真正发布的  
\- Brownfield vs Greenfield 区分是胡扯，没大家想的差别那么大  
  
字幕：AI 辅助转录 + 翻译并经人工校对。如有不准确之处，欢迎指出。
