# lint：知识库体检

对 `知识库/` 做系统性健康检查，产出报告，低风险问题自动修复，高风险问题只报告留待用户判断。

**检查项：**

> **非页面文件**：`索引.md`、`操作日志.md`、`综述.md`、`lint-report-*.md`——它们是索引／日志／
> 生成产物，不参与下面的孤儿页、索引同步、frontmatter 三项检查。

## 1. 结构完整性

- [ ] **断链**：扫描所有 `[[]]`，检查目标是否存在。**注意本库链接解析有三个根**——wiki 内部链接（`[[摘要/X]]`）在 `知识库/` 下解析，跨层链接（`[[原始资料/剪藏/X]]`）在 vault 根解析，短链（`[[清结算]]`）需在 `知识库/` 下递归查找。三者都要试，只试一个根会全部误报。
  - 本库**合法存在跨层同名文件**（`原始资料/剪藏/X.md` 与 `知识库/摘要/X.md` 同时存在是有意的，因为 Obsidian 按文件名全局解析 wikilink）。不要把这种重复当问题，也不要建议改名。
- [ ] **孤儿页**：无任何入链的页面（非页面文件除外）
- [ ] **索引同步**：`知识库/{摘要,概念,实体,综合,输出}/` 下的页面是否都在 `索引.md` 中列出

## 2. frontmatter 合规

- [ ] **必填字段**：每个页面是否有 `title`、`tldr`、`type`、`status`、`created`、`updated`（非页面文件除外）
- [ ] **type 合法**：是否为 `source` / `entity` / `concept` / `synthesis` / `output` 之一（非页面文件除外）
- [ ] **status 合法**：是否为 `stub` / `draft` / `stable` / `needs-review` 之一（非页面文件除外）

## 3. 内容质量

- [ ] **矛盾未标注**：是否有两页提出冲突结论但未用 `> [!contradiction]` callout 标注
- [ ] **缺口未标明**：概念页/摘要页是否缺少反方观点或数据缺口说明
- [ ] **stub 僵局**：`status: stub` 的页面是否长期未扩充
- [ ] **积压**：`status: needs-review` 与 `confidence: low` 的页面是否长期未处理
- [ ] **过时内容**：`updated` 超过 6 个月的页面

**输出：**

1. 生成报告到 `知识库/lint-report-YYYY-MM-DD.md`
2. **低风险问题自动修复**：`索引.md` 漏条目、简单 typo 等
3. **高风险问题仅报告**：矛盾标注、内容过时等需用户判断
4. 追加 `知识库/操作日志.md`：`## [YYYY-MM-DD] lint | 检查结果摘要`

**约束：** lint 不得修改 `原始资料/` 下任何文件。
